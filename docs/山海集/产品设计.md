## 1. 产品定位

**按地点保存、找回并分享自己的旅行回忆。**

摄影册决定阅读风格，地图负责组织地点，照片和个人故事才是核心内容。用户不需要维护复杂行程、写完整游记，先留下值得记住的一次到访即可。

- 首发目标：中国境内旅行记录；当前可选择 34 个省区并添加个人地点，公共目录仍为云南 43 处。粗略边界可能拒绝沿海、岛屿及省界附近的真实位置；完成省区选择不等于完成全国公共景点覆盖。
- 当前主要形态：响应式Web，普通 `/app` 使用本机浏览器存储；`/connected` 显式接通这台电脑的测试账号服务，尚非正式云服务。当前在电脑上开发和试跑，手机端真实体验尚待验收。
- 当前主要任务：记录一次旅行 → 以后按线索找回 → 精选一张卡片给朋友看。
- 当前不承诺：自动整理整本相册、永久云端保管、实际行走轨迹、完整旅行攻略或全国景点覆盖。

## 2. 用户与价值假设

### 2.1 初始目标用户

有值得保留的旅行照片、愿意精选少量内容，并习惯借助地点回想旅行的人。首轮优先选择有云南旅行内容的参与者；这是待验证的用户假设，不是已证实的市场人群。

### 2.2 已知问题与证据

产品提出者曾反馈：为了发给朋友看，打开 Apple 相册向上翻，最后没有找到想要的照片。这是一次回顾性自述，尚未确认当时记得哪些线索、有没有尝试搜索或困难出现频率。

截至现有试跑记录，F01 仅是产品提出者的流程校准，未完成整套任务；独立用户试用完成数为 0。不能把程序回归通过、设计喜好或这一次自述当作需求成立、优于其他产品或有留存的证明。见 [F01 记录](../../山海集-试跑记录-F01.md)。

### 2.3 要验证的差异

| 用户获得的价值 | 当前设计手段 | 仍需验证 |
| --- | --- | --- |
| 更容易认出自己去过的地方 | 简化地标、自己的足迹优先、公共点与个人记录区分 | 地图是否真的帮助回想，而不只是好看 |
| 找到具体某次到访 | 地点、日期、手记检索；结果直接指向匹配记录 | 用户实际记得的线索是否足够 |
| 愿意花一点时间整理 | 照片优先、默认封面、手记选填、草稿恢复 | 录入成本是否值得未来收益 |
| 更方便向朋友讲述 | 精选照片生成回忆卡、可控文字与日期、系统分享或下载 | 是否确有分享意图且能完成交付 |

地标、地图与手账外观是产品辨识度，不宣称已经构成竞争壁垒。用户内容可导出，不通过限制迁移制造依赖。

## 4. 信息架构与界面职责

```text
地图首页
├── 记一下 / 继续草稿
│   └── 照片 → 地点 → 日期 → 可选手记 → 保存
├── 我的足迹 / 全部景点
│   ├── 地点、日期、手记搜索
│   └── 州市筛选
├── 景点与回忆
│   ├── 未记录：地点简介 → 记录入口 → 来源
│   ├── 已记录：多次到访 → 照片查看 → 编辑 / 删除
│   ├── 搜索进入：匹配回忆 → 可切到全部回忆
│   └── 分享回忆卡 → 预览 → 系统分享 / 保存图片
└── 备份与恢复 / 地图与数据说明
```

这是普通本机模式的单页界面层次；景点详情在侧栏或窄屏下方切换，不是独立URL景点页。账号入口 `/connected` 复用地图/编辑器等组件，另加连接状态、重新同步、待保存重试和退出；隐藏未实现的账号备份恢复与删除撤销，不沿用本机能力作出承诺。

### 4.1 初次进入

- 无记录时显示全国省区总览与实际公共目录覆盖说明；点击省区轮廓或选择框进入某地。公共目录不是虚构的个人足迹。空目录提供“没有这个地点？自己记一个”，不把未收录写成该省没有景点。
- 入口优先级：记一下 → 找地点 → 浏览地图；不增加账户注册和旅程整理前置步骤。
- 未完成本地读取时显示加载状态；读取失败提供重新读取，不把失败误当作空相册。

### 4.2 回访首页

- 本地已有回忆时，首次读取后优先进入“我的足迹”，按最近到访日期排列地点。
- 地点数为不同地点的数量，回忆数为记录数量；同一地点去过多次仍是一个足迹地点。
- 可随时切到全部景点。公共景点和个人记录共用地图，但有回忆的地点才带个人状态提示。

### 4.3 地图与密度

- 地标底部锚点对应真实代表坐标，拥挤时聚合，放大或点击聚合进入成员；不随意挪动坐标来排版。
- 聚合“几处”表示附近地点数量，不是照片数量或到访次数。
- 地图已显示自己的轻量照片封面，多张时带叠片后缘，单张不制造多张错觉。地标主体保留 54/58/64px 档位；照片纸面最大 48×44px，窄屏紧凑档 44×44px，包含后缘的外框为 52×48px 或 48×48px，避免再次用大照片遮住雪山。
- 照片优先放地标侧边，再考虑下方；对地标、地名、控件、聚合数量和其他照片避让。空间不足采用紧凑档、折叠封面或地点聚合，不移动地理锚点；锚点已离开视野时不把照片单独拉回屏幕。聚合只使用锚点地点自己的照片，不借其他成员照片冒充。
- 地图与列表共享精选规则：有效的地点手选封面优先，否则取最近有图回忆的记录封面或首图。日期/手记命中具体回忆时只在匹配回忆中选图，匹配项无图不借别次照片；仅命中地点名称则保留地点精选。可见照片复用共享 loader，离屏取消并释放，不传入整本图库。
- 这是用户原始核心要求的工程实现，已用合成数据做桌面及 390/320 宽度检查；触摸体验与真实手机仍待验，不等于 AI 地标、3D 或全国覆盖已经完成。
- 代表点可能是山峰、湖心或建筑，不表示景区入口、导航目的地或完整行走路线。
- 自定义点只代表用户确认的位置，不冒充官方地标或已核实景点。

## 5. 核心流程与规则

### 5.1 新增回忆

1. 从首页开始，或从具体地点“再记一次”进入并预填地点。
2. 选择照片；第一张默认封面，允许主动改选或移除。
3. 确认地点、到访日期，可写一句手记。
4. 保存成功后进入该地点回忆；失败保留当前内容，不能只凭点击按钮判断已保存。

| 输入 | 当前规则 |
| --- | --- |
| 照片 | 0–9 张，累计包含已有照片；每张原文件最多 10 MiB |
| 内容最低要求 | 至少一张成功处理的照片或一段非空白手记 |
| 格式 | JPEG、PNG、WebP；HEIC/HEIF 取决于浏览器解码能力，失败提示转 JPEG |
| 展示副本 | 本机转换为最长边不超过 2000 像素的 JPEG，不放大原图；不保留定位等 EXIF |
| 到访日期 | 必填，默认今天，允许补录过去，不允许未来日期；不从照片自动推断 |
| 手记 | 选填，最多 2000；当前表单按 JavaScript 字符串长度限制 |
| 自定义地点 | 名称 1–60、手选省区（云南另选州市）、在所选省区示意轮廓内确认位置；更换省区清空旧坐标，不自动补全或证明行政归属 |
| 同日同地点 | 普通新增会提示已有记录，确认后才新增；编辑已有记录的日期/地点不触发这条重复提醒，不自动合并或覆盖其他记录 |

照片压缩的是网页副本，不会删除或修改原相册。当前不是原图备份服务。

上述去 EXIF 规则只适用于新选择照片并经 Canvas 重编码的流程；从旧备份恢复的 JPEG/PNG 会保留其图片数据，不再次去除元数据。处理后的新增图片也受单张 10 MiB 校验。照片中的人脸、门牌等可见内容不会因去 EXIF 消失，分享前仍需自行检查预览。

同名自定义地点不自动去重：地点身份以 `placeId` 为准，不以名称相同作为同一个地方。再次去同一自定义地点应选择已有地点；重新创建同名地点会得到独立身份。省内判断基于当前简化轮廓，边界附近或不确定的位置应取消确认，不视为专业地理校验。

### 5.2 找回与阅读

- 检索字段：地点名、别名、城市/州市、到访日期、手记；可叠加州市和“我去过的”筛选。
- 查询统一处理全半角、大小写和空白差异，但不是模糊语义搜索或图片内容检索。
- 多段回忆同时命中时仍按到访日期、创建时间倒序排列，不是相关度排序；清空搜索只去掉关键词，保留省区、州市和到访筛选。“回到全国总览”重置筛选；“我的足迹”在全国范围查找有回忆的地点。取点时省区锁定，“回到所选省区”只恢复正在选择的省区视野。
- 结果优先显示匹配到访的日期、照片封面和短摘要；进入后先看匹配记录，可切换为该地点全部回忆。
- 地点列表每批 12 处；同地点回忆每批 8 段，加载更多保留顺序并聚焦新增内容。
- 没有结果应提示换关键词或筛选；不能把筛选后的空结果描述成“从未记录”。
- 纯手记记录正常阅读、编辑和生成文字卡，不借用别次到访的照片。
- 当前 Vue 首页只读取无照片字节的记录摘要，并检查是否存在活动草稿；打开编辑器时才读取完整草稿。可见封面按需读取，离开可见区域释放页面图片；照片失败显示明确入口，仍可点开完整回忆重试。
- 点击看图、编辑、删除或制作回忆卡时，按记录 ID 读取整条回忆并核对目录版本。读取失败或目录已过期时保留页面内容、要求重新读取，不依据旧摘要继续写入。该优化不是缩略图生成，也没有把照片移出原记录。

### 5.3 草稿、纠错和删除

- 输入后自动保存一份本机草稿；以“草稿已保存到本机”为准，处理中或失败时不建议刷新。
- 有草稿时，新入口先继续现有草稿，不直接用另一次新增/编辑覆盖它。
- 多页出现版本冲突时保留本页内容；载入另一页草稿需要再次确认，因为它会替换本页未保存的内容。
- 同一草稿已被另一页保存为回忆但内容不同时，按明确两步确认另存为新记录；不静默覆盖已保存记录。
- 原 8767 构建中，另一页清空后仅保留本页内容。开发版已提供“检查草稿状态 → 确认另存本页草稿”，确认时检查共享槽仍为空，另一页已占用则拒绝覆盖；另存草稿后仍需正式保存回忆。
- 已保存回忆可改日期、地点、照片、封面和手记；过期编辑不能覆盖另一页的较新修改。
- 移除当前封面照片后，自动选剩余第一张；没有照片时封面为空。查看照片或选择卡片照片不会更改记录封面。
- 删除先说明日期及照片数量并确认；只删除网页中的记录副本，保留原相册文件。当前页面只能撤销最近一次删除，刷新后撤销失效。
- 自定义地点修改不静默移动其他记录；删除最后一条关联回忆后，该自定义点不再显示。

### 5.4 回忆卡与分享

Vue 已实现本节规则，并完成桌面浏览器验证，见 [分享卡验收报告](../../shanhai-app/qa/sharecard-20260907/REPORT.md)。系统文件落盘、真实发送与真机仍单独标为未通过验收。

- 用户从一段回忆中选 0–3 张照片，或仅以文字制作卡片；文字与日期由用户主动选择，先预览再输出。
- 输出为 1080×1440 PNG。只分享当前生成图片，不自动带上完整备份、所有照片或其他手记。
- 有文件分享能力时显示“系统分享”；不支持时保留“保存图片”，用户再手动发送。
- 取消、失败保留预览与重试机会；程序提示交给系统不等于接收者已经收到。
- 当前没有公开作品页、私密链接、访问密码或分享访问统计。
- 卡片内编辑的文字、所选照片和是否带日期只影响此次输出，不改写原回忆手记或封面。没有照片时必须有非空卡片文字；完全空白不能生成。
- 默认不带入原手记，也不勾选日期；需要时主动填写、带入手记或勾选。照片按原记录顺序输出，最多 3 张，不按勾选顺序重排。
- 每次打开取一份独立选择快照，地点名来自已校验目录并固定；后台刷新不能改掉本次标题或选择。预览预留 1080×1440 比例，生成后图片完整可见，避免解码后布局跳动。

### 5.5 备份与隐私

- 普通 `/app` 默认仅存当前设备、浏览器、访问来源的IndexedDB，不要求登录、不自动上传。`/connected` 只有明确保存才将照片副本和手记上传到本机测试服务；草稿仅在本浏览器按账号保留，退出不清空已存草稿/outbox，但卸载当前私人界面。已接通不代表正式云同步交付，也不代表Windows文件ACL已通过保密认证。
- 普通本机模式换协议、主机名或端口属于不同来源，不自动共用记录；同网址的其他设备也不会同步。后端独立会话读取不等于普通本机库已迁移。
- 完整备份包括当前格式定义的已保存记录、照片、封面与自定义地点，不含未完成草稿或会话内撤销记录，也不承诺保留外部文件的任意扩展字段。
- 导入先校验，再合并；相同内容可去重，冲突不无提示覆盖。备份含私人内容，不能当作公开分享卡发送。
- 本机备份导入不是整库回退：本机新增而备份里没有的记录仍保留；备份里有、后来在本机删除的记录可能被重新加入。本机备份没有跨设备删除同步或删除历史标记，不能与后端提交级墓碑混为一谈。记录删除后，用户自行保存的旧备份、下载卡片和已发送图片不会被自动撤回。
- 原 8767 的单文件 v1 限 100 MiB、2000 条记录。当前正常导出统一生成 v2：按固定目录版本逐条读取，逐卷写入本机临时副本，核对后提供卷列表；每图 10 MiB、每条最多 9 图、每卷包装后 100 MiB 的格式边界保留。旧 `prepareExport` 与 v1 collector 仅保留兼容用途。
- 生成需要额外本机临时空间；副本未加密，含照片与手记。用户先准备一卷，再主动点击下载；页面只保留一个活动导出链接，点击只标“已发起”，不表示系统已经保存。已生成副本可继续逐卷下载，确认文件保管完成后明确清理。
- 生成时另一页修改记录或封面会终止本次生成；取消或失败只清理本次拥有的临时副本，原库和其他副本保留。身份可确认的损坏或未完成副本仍可见并可指定清理；身份无法确认时拒绝猜测目标，不自动续拼、修补或回退到整库内存导出。分卷不代表无限存储或大型手机照片库已经可用，不可为导出而先删重要记录。
- 清除网站数据、隐私模式关闭、浏览器回收或设备故障可能造成丢失。普通本机库未提供文件加密、账户隔离或永久保管承诺；后端的逻辑账户隔离不等于 Windows 多用户文件保密认证，敏感内容仍需保护设备及备份。
- schema 1/2→3 同源升级已在专用合成来源验证保留数据；这不是已经迁移用户的 8767 库。升级后旧页面可能拒绝读取新版库，换回旧网页不等于数据回退；不能以清库恢复启动，也不自动用旧备份覆盖现库。
- 照片索引阶段 schema 3→4 仅增加摘要索引和版本元数据，原生隔离库的原记录、照片、地点封面和草稿签名保持；不等于真实大型库或慢手机已经完成迁移验收。当前地图改动不升级 schema，升级失败不能通过删除原库处理。

## 6. 视觉与交互原则

- 延续已确认的旅行摄影册＋手账地图：暖纸色、松墨文字、少量印章红、低对比地理底图，避免新的视觉系统打断现有体验。
- 地名用宋体气质标题，正文与操作用易读系统字体；照片是内容，不增加地图上的大型照片装饰。
- 桌面以地图与回忆侧栏协作，窄屏上下组织；主要操作清晰，管理、来源、备份按需展开。
- 照片查看保留完整比例；封面是阅读入口，不等于原图永久保管。
- 保留键盘可达、可见焦点、操作后焦点回到合理位置、状态/错误提示和减少动画偏好。窄屏检查不能替代真机触摸与系统文件流程。
