## 1. 架构定位与边界

山海集普通 `/app` 仍是“本机优先”的静态Web应用；独立 `/connected` 复用实际地图/编辑器并接通本机业务后端，显式保存才上传。它是测试身份的限定账号闭环，不是正式身份、公网云同步或旧库迁移产品。

- 产品首发目标是中国境内；当前可选 34 个省区并添加个人地点，公共目录仍为云南 43 个代表点、16 个州市；全国公共目录和整体首发目标未完成。
- 测试身份、服务端私人记录/照片、提交级同步API及Vue核心接通已限定验收；仍无正式身份、云同步、云对象存储、远程AI或付费地图接口，不能写成“已上云”。账号模式禁用备份导入导出与删除撤销。
- 旧 Python 静态服务、Vue 的本机 Vite 预览与新独立 Node 试用服务只交付页面，不保存照片和手记；停止服务不主动删除浏览器记录。
- 真实足迹来源是用户保存的地点回忆，不是设备定位、GPS 轨迹或后台自动打卡。
- 普通本机前端没有独立的 `Trip`、`Guide`、`User` 业务实体；后端已有测试 `accounts/sessions`，连接模式不等于正式身份系统。没有行程自动合并、攻略社区或景点3D页面。

账号库名为 `shanhai-account-v1-<server UUID>`，不是匿名主库升级。完整commit的实体摘要与cursor同事务写入；首次从保留change回放，未实现持久固定快照。草稿留在本浏览器，outbox保留原输入、操作键、上传代次与步骤，先查原收据再重试；结果未知不标保存成功，已完成操作清除输入照片。关闭/错账号使实例失效、取消请求并卸载私人树，持久账号草稿/队列仍保留。没有后台自动上传匿名库，也不承诺离线首次登录或无限历史回放的性能。

原生发现的两项修复：同草稿明确另存新身份时，新草稿与旧目标终态conflict归档同事务提交，有未知pending则拒绝换身份；真正关闭编辑器后重新读取摘要，失败禁用旧操作，保存自有刷新不重复，卸载后迟到读不落地。普通本机备份、分享卡、草稿模型仍保持兼容；账号备份/恢复和删除撤销明确禁用。详见 [适配器约束](../../shanhai-app/qa/vue-integration-20260907/REMOTE.md)。

## 2. 构建与加载链

Vue 构建入口是 [package.json](../../shanhai-app/package.json) 与 `src/main.ts`，运行 `npm run build` 经类型检查后由 Vite 输出 `dist`；`npm run preview` 在本机 5174 预览该产物。公共资源已在工程中，运行时不依赖旧目录。内核同步由 `scripts/sync-legacy-kernels.mjs` 显式执行，`verify` 对照旧权威源码检查，不能手改生成 JS。

`vite.config.ts` 将基础省界 `regions`、景点 `places`、vendor 与应用入口拆为独立哈希资源，并生成 `.vite/manifest.json`。`regions` 含全国粗略省界和原云南精细轮廓，仍是同步校验依赖；完整云南 25 个 feature 不再进入 JS 图，而由 `geography-service.ts` 在进入云南时 `fetch('/data/yunnan-geography.geojson', {cache:'no-cache', signal})`，15 秒超时，失败保留省界、回忆及草稿。服务共享正在进行的读取，单个调用取消不影响其他调用，关闭时中止网络；App 防止旧省份晚到响应覆盖当前视图。

当前 [全国省区体积记录](../../shanhai-app/qa/national-map-20260907/bundle-measurement.json)：入口 208,675 字节；首次 5 个 JS 合计 907,471 字节、逐文件 gzip 287,177 字节；CSS 48,662 字节。延迟云南 JSON 单列为 1,042,040 字节、gzip 373,914 字节。[初始请求](../../shanhai-app/qa/national-map-20260907/network-initial.json) 未读取该 JSON，[重试请求](../../shanhai-app/qa/national-map-20260907/network-retry.json) 记录首次 503、用户重试后 200。这是限定桌面网络证据，gzip 是 Node zlib level 6 离线测量，不代表服务已压缩、实际延迟或手机性能。

历史测量分别保留：增量导出阶段入口/首次 JS/gzip 为 199,286 / 1,490,843 / 515,658 字节，几何当时仍为静态 JS 1,041,524 字节，见 [历史导出测量](../../shanhai-app/qa/incremental-export-20260907/bundle-measurement.json)；地图阶段 172,851 / 1,464,408 / 508,339 字节见 [历史地图测量](../../shanhai-app/qa/map-covers-20260907/bundle-measurement.json)；索引阶段 167,924 / 1,459,481 / 506,691 字节见 [历史索引测量](../../shanhai-app/qa/photo-index-20260907/bundle-measurement.json)。不将历史静态几何口径用于当前按需数据。

以下是原生旧版维护链路；其开发源码已有新修复，产物应通过 `--out-dir` 写入明确隔离目录，避免替换原 8767 文件。构建入口为 [build.mjs](../../output/shanhai-yunnan/build.mjs)：

1. 读取当前目录的 `places.json` 和 `geography/data.json`，生成内嵌 `ShanhaiYunnanData`。
2. 合并本地 `vendor/leaflet.js`，随后按顺序载入 `catalog.js`、`map-layout.js`、`landmark-icons.js`、`photo-import.js`、`memory-editor.js`。
3. 从旧目录复用 `backup-codec.js`、`local-store.js`、`photo-viewer.js`、`memory-card-renderer.js`、`memory-card-ui.js`、`backup-ui.js`。
4. 最后载入当前目录的 `app.js`；模块定义先于实际应用初始化，旧目录不是另一套必须同时运行的服务。
5. 合并 Leaflet、复用组件及当前 `app.css`，与 `app.html` 生成自包含 `index.html`；用 `vm.Script` 检查脚本语法。
6. 输出 `build-report.json`，记录构建时间、景点/地理数量、字节数和 SHA-256。

两套入口都先建立公共目录与界面。旧版随后读取完整记录/草稿；当前 Vue 通过类型化 `repository.loadIndex()` 校验摘要、重建自定义地点目录和足迹，以 `hasDraft()` 判断入口，不在首页读取整份照片草稿。首次成功读取后才决定进入我的足迹或公共目录；读取失败不能当作空库。

`build.mjs --publish-local` 是兼容旧目录的可选维护动作，会先保留旧 `index.html` 快照再复制；正常构建只更新云南目录产物，不启动服务、不上传文件。

## 3. 模块职责与依赖方向

当前 Vue 的主要入口是 `src/App.vue`、`src/components`、`src/domain`、`src/editor`、`src/sharing`、`src/services` 和 `src/generated`，详见 [产品代码结构](产品代码结构.md)。UI 通过类型化服务处理业务和平台能力，内核不负责 Vue DOM；`MemoryCard.vue`/`memory-card.css` 管理卡片交互，`sharing/card-types.ts`/`card-renderer.ts` 提供明确输出契约与独立渲染。`BackupExport.vue` 管理导出列表与单卷链接；`export-types.ts` 定义轻量契约，`export-store.ts` 负责独立 IndexedDB，`export-service.ts` 编排来源读取、校验、ready 与清理。下表保留旧版模块及兼容内核权威来源，便于维护跨版本规则：

| 层 | 旧版 / 兼容模块 | 职责与约束 |
| --- | --- | --- |
| 页面与协调 | `app.html`、`app.css`、`app.js` | 页面状态、地图/列表/详情切换、组件装配、错误反馈；不直接实现 IndexedDB 事务 |
| 地点目录 | `catalog.js` / `ShanhaiPlaces` | 公共目录、州市和地图范围；校验、重建随回忆保存的自定义地点 |
| 地图表达 | `map-layout.js`、`landmark-icons.js`、本地 Leaflet | 地标 SVG、像素距离聚合、筛选和匹配规则；不改变地标原始坐标来避让 |
| 照片输入 | `photo-import.js` / `ShanhaiPhotoImport` | 文件签名检查、顺序解码、缩放与 JPEG 副本生成 |
| 编辑流程 | `memory-editor.js` / `createShanhaiMemoryEditor` | 表单、草稿队列、地点选取、封面、编辑原始版本、重复与冲突确认 |
| 数据规则 | `backup-codec.js` / `ShanhaiBackup` | 记录与备份校验、序列化、摘要和保守合并计划 |
| 持久化 | `local-store.js` / `createShanhaiLocalStore` | IndexedDB 连接、迁移、事务、记录版本检查、草稿 CAS、备份原子合并 |
| 观看与输出 | `photo-viewer.js`、`memory-card-*.js`、`backup-ui.js` | 查看照片、卡片生成/预览/分享、私人备份交互 |
| 交付 | `serve.py`、`package.mjs` | 白名单静态路由、公开文件打包、哈希清单与隔离检查 |

上表旧版模块以 IIFE 和 `globalThis` 注册接口；Vue 使用 ES Module 和组件，机械生成内核以依赖注入替代旧全局绑定。修改权威存储/备份算法时要同步生成物，并同时检查两套入口的兼容测试。

## 4. 当前数据模型

4.1–4.4 描述正式 Vue 前端的本机模型；新增后端模型另见 4.5，不能把服务端 UUID/照片引用直接当作原 `Visit` 或备份字段。

### 4.1 公共地点与自定义地点

当前公共地点来自工程内 [places.json](../../shanhai-app/src/data/places.json)，保留旧云南 43 点身份及来源；全国归属约束见 [全国地点数据契约](全国地点数据契约.md)。核心字段如下。

| 字段 | 含义 |
| --- | --- |
| `id`、`name`、`aliases` | 稳定景点标识、展示名、检索别名 |
| `regionId`、`regionName`、`city` | 当前记录区域与检索文字；云南为州市，其他省暂为省级 |
| `coordinates`、`coordinateSystem` | `[经度, 纬度]`，统一 WGS84 |
| `category`、`iconKey`、`priority` | 分类、SVG 意象选择、展示/聚合排序；不是热度评分 |
| `text`、`highlights`、`source` | 本地简短介绍、亮点和公开资料来源 |
| `coordinateSource`、`anchorNote` | 坐标证据及代表点含义，不等同于攻略或入口导航 |

公共 43 点的 `mapId` 保持 `yunnan`，个人地点则从 `regionId` 推导省级 `mapId`。`Province` 有 `id/code/name/shortName`；云南省 ID 保留 `yunnan`，其余为已登记的 `cn-11` 等稳定 ID。49 个 `Region` 保留旧云南 16 个州市 ID，再加入其他 33 个省级区域；不能把它们当作全国完整城市清单。`yulong` 等旧 place ID 不变。

普通本机前端自定义地点仍仅持久保存 `id`、`name`、`regionId`、`coordinates`，以 `visit.customPlace` 嵌入回忆；`Visit`、`Draft` 不新增持久化 `provinceId`，匿名库没有单独地点表。其主库schema4、独立导出库schema1、备份v1/v2不因接通改变；账号适配器另把服务端地点投影进独立cache，不重写旧身份。

自定义 `id` 以 `custom-` 开头，名称去首尾空白后 1–60 字；`regionId` 必须属于当前 49 项。云南仍存 `lijiang` 等旧州市 ID，其他省存 `cn-11`、`cn-51` 等省级 ID，坐标按该省多边形及孔洞校验；非有限数、越界、未知省份和仅落包围盒内的点拒绝。云南沿用原 8,335 坐标轮廓，旧规则不放宽；其他省轮廓粗略，边缘点可能被误判。省区变更后编辑器清空旧坐标。用户选择的区域不等于精确行政反查。

加载有效回忆后，`replaceCustomPlaces(visits)` 重新生成个人目录；删除最后一条关联回忆后，该自定义地点不再显示。修改某条回忆中的地点信息不会批量改写其他回忆；已有同编号地点内容变更时由编辑器生成新的自定义地点编号。

### 4.2 正式回忆、照片与封面

```text
Visit
  id: string                     // 记录主键
  createdAt: number               // 创建时间；编辑保留原值
  placeId: string                 // 公共目录 ID 或 custom- ID
  date: "YYYY-MM-DD"             // 用户确认的到访日期，不晚于今天
  note: string                   // 最多 2000 个 JS 字符长度单位
  photos: [{ id, name, url }]     // 每条最多 9 张，url 是内嵌图片数据
  coverId: string | null          // 必须对应本记录照片；无照片时为 null
  customPlace?: { id, name, regionId, coordinates }

CoverReference
  placeId: string
  visitId: string
  photoId: string
```

每条回忆至少包含一张照片或非空手记。普通本机新增照片储存为JPEG data URL，备份兼容已保存JPEG/PNG；图片与文字仍在同一记录中，没有Blob表、云URL或原图文件副本。账号模式摘要只有照片引用，打开时按需获取服务端重编码JPEG、核长度/hash后映射为现有组件可用data URL；草稿/未完成outbox可保留输入字节，不能把账号摘要无图字节误称全库无图字节。

`photo.name` 仅作展示名称，不表示原文件被保存。新增照片经过重编码去 EXIF；备份导入检查后保留备份中的图片 data URL，不再编码或清理元数据，不能承诺所有历史照片都没有定位信息。编辑保留 `id/createdAt`；确认另存才生成新 `visitId` 和新的创建时间，`date` 仍是用户确认的到访日期。

`coverId` 是单条回忆封面；`covers` 是地点级手选照片引用。地图和列表已共用 `selectPlaceCover(placeId,recordIndex,covers,query)`：有效地点精选优先，否则最近有图回忆的 `coverId` 或首图；日期/手记命中时只在匹配记录中选，匹配无图不借其他记录，只有地点名称命中时保留普通精选。返回 `visitId/photoId/photoName/photoCount`，不携带 URL 或完整 Visit；详情仍使用记录封面。封面变更后的摘要 revision 刷新使地图/列表一起更新，不另存第二套地图封面。

### 4.3 草稿与存储版本

IndexedDB 默认名称为 `shanhai-lijiang-local-v1`。原 8767 构建使用 schema **2**，上一阶段独立包使用 **3**，当前权威内核与 Vue 使用 **4**；名称中的 `v1` 不是 schema。schema 3 增加暂存，schema 4 增加派生摘要和库版本，不重写原 `visits/covers/drafts`：

| Object Store | keyPath | 内容 |
| --- | --- | --- |
| `visits` | `id` | 正式回忆及其内嵌照片、自定义地点 |
| `covers` | `placeId` | 地点级封面引用，保留兼容 |
| `drafts` | `slot` | 单个 `{slot: 'active', draft: {...}}` 活动草稿 |
| `backupImportSessions` | `id` | 本次导入元数据、阶段、计数和提交收据 |
| `backupImportVisits` | `[sessionId, id]` | 分会话暂存回忆；`sessionPlace` 索引核对地点 |
| `backupImportCovers` | `[sessionId, placeId]` | 分会话暂存封面引用 |
| `visitIndex` | `id` | `VisitSummary`：保留记录元数据，照片仅 `{id,name}`，没有 `url` 字节 |
| `libraryMeta` | `id` | `{id:'library',revision}`，为摘要/单记录一致性提供库级版本 |

schema 4 升级用游标逐条投影旧记录；摘要校验失败时终止整个升级，不删旧行或跳过异常行。正式新增、编辑、删除、撤销与导入在同一事务内维护 `visitIndex`，正式回忆/封面写入的事务同时更新 `libraryMeta.revision`；不是先写原记录再异步补索引。

打开库的 8 秒超时及 `close()` 遇到仍活跃的升级事务时先发起 abort，等终止事件确认再报失败，防止重试与未结束迁移竞态；已越过提交边界时依实际结果处理，不伪称已回滚。该受控边界已测试，但真实大库、慢设备是否能在当前时限内完成迁移仍待量测。

草稿字段为 `id`、`visitId`、`createdAt`、`placeId`、`date`、`note`、`photos`、`coverId`、`updatedAt`，以及保存生成的 `version`；可选 `customPlace`、编辑用的 `originalVisit`。

草稿允许地点或文字尚未填完，不能直接等同于有效正式回忆。系统只维护一份活动草稿；继续其他记录前应先处理它。草稿不是历史版本库，也不随私人备份导出。

备份有独立格式：v1 为 `{format: 'shanhai-backup', version: 1, exportedAt, visits, covers}`；v2 使用 `shanhai-backup-volume` 清单与分卷。修改 schema 不等于提升备份格式版本；提交收据和未完成暂存不随普通备份导出。

### 4.4 独立导出暂存库

`travel-services.ts` 显式创建 `${dbName}-exports-v1`，默认 `shanhai-lijiang-local-v1-exports-v1`；首次使用才打开，schema 为 1，仅有 `sessions`（主键 `id`）与 `parts`（主键 `[sessionId,part]`）。这不是主库的新表，也不复用导入会话。`parts` 保存单卷 UTF-8 Blob、bytes、sha256；`sessions` 保存固定来源版本、清单、卷文件元数据与状态，不含完整照片数组。

状态为 `building → ready` 或 `deleting → 删除`。公开描述符隐藏写入令牌；仅在 id/sourceDbName 可确认时，损坏元数据投影为可识别、可指定清理的 `damaged`，不能下载；身份本身无法确认则拒绝读取，不猜测清理目标。追加和完成在事务中核对会话状态及私有 writer token；自动失败清理在置 deleting 和删除 parts 两阶段均核对所有权，ID 碰撞不能清理其他会话。明确用户清理可终止选定副本，先使写入失效，再删除该会话 parts；已下载文件与已交给其他页面的 Blob 不可撤回。

### 4.5 独立后端数据与生命周期

[001_initial.sql](../../shanhai-api/migrations/001_initial.sql) 创建 `accounts/sessions`、`custom_places/visits/photos/uploads/map_covers`、`mutation_receipts/sync_commits`、`download_grants/cleanup_tasks` 与服务签名密钥表；迁移记录核对 SQL 哈希。owner 从会话推导，外部字段白名单拒绝注入；私人关联有带 owner 的复合外键，业务层再核对照片、回忆和地点从属。

- 服务端 `custom_places` 独立存储；`visits` 引用公共稳定 ID 或自有地点 UUID，照片只存有序 ID 引用与 `coverPhotoId`。照片元数据含输入/输出 SHA-256，实际 JPEG 在私有对象目录；接口不返回内部路径，业务收据/change 不保存签名 URL。
- 业务变更在同一 PostgreSQL 事务内锁定账号、重核会话、比较版本、修改数据、写提交级 change 和幂等收据。同键不同请求拒绝；删除后的 client ID 不释放，照片/回忆/地图封面墓碑按完整提交返回。列表 cursor 在库版本变化时要求重列，不是持久固定快照 API。
- 上传先持久化预留及清理意图，再用绑定会话/代次的 5 分钟 capability 接收一次真实字节；检查长度/SHA-256 后，由 sharp 验证 JPEG/PNG/WebP、单页与 40 MP 上限，重编码为最长边 2400 像素 JPEG。暂存读取故障为可重试 503；真实损坏/解码失败才拒绝并退休。
- 单图输入/输出各限 10 MiB；每账号最多 500 个占用中的照片身份、100 MiB 保守预算，计算输入预留、实际输出及待清理对象。读取仅向 ready 且挂接有效自有回忆的照片签发 60 秒能力，每次再检查会话/对象状态；注销不能撤回已经下载的副本。
- GC 先提交退休状态/墓碑，再独立删除精确对象并确认，失败保留可重试任务；当前由显式 `/cleanup/retry` 驱动，没有后台定时 GC。墓碑、收据和历史 change 的保留不等于立即物理擦除，也未实现账号删除/保留期策略。

后端不自动读取或迁移匿名IndexedDB；Vue账号缓存/草稿/outbox已实现，断点迁移UI、持久固定快照、真实身份/OIDC、云对象存储或多节点限流尚未完成。六个北京/四川公共地点仅为 [来源候选](../../shanhai-app/qa/catalogue-expansion-20260907/place-candidates.json)，未写入生产目录。后端固定 `catalogueVersion=yunnan43-3ecd736f`、`validationVersion=national-20260907-b6918bc0`，启动核对34省界、旧云南轮廓与43点哈希。

## 5. 前端核心数据流

### 5.1 新增一段回忆

1. 用户点击“记一下”，编辑器创建草稿 ID 与稳定的目标 `visitId`，日期默认为本机今天。
2. 用户选择照片；检查累计最多 9 张、单原文件不超过 10 MiB，识别文件头而非仅信任扩展名。
3. 浏览器顺序解码 JPEG/PNG/WebP 或能原生解码的 HEIC/HEIF；Canvas 输出最长边不超过 2000 像素、质量参数 0.86 的 JPEG 副本，去除原 EXIF，不修改相册原文件。
4. 单张失败显示原因，已成功处理项保留；一次选择超过剩余张数则整批不加入。首张默认封面，用户可修改。
5. 用户确认地点、日期、照片或手记，经 `ShanhaiBackup.normalizeSnapshot` 校验，再进入正式保存。
6. Vue 保存前读取 `loadIndex()`；普通新增用摘要检查同日同地点，只有相同记录 ID 已存在时才调用 `readVisit(id,{expectedRevision})` 比较完整内容。编辑继续使用打开时原快照 CAS，不把摘要伪装成完整 `Visit`；新记录使用 `addVisit`，不是无条件 `put` 覆盖。
7. 事务完成后清理对应草稿、刷新目录与视图，并选择记录所属省份及地点；显式地点定位优先于省区切换的通用缩放。清理草稿失败与正式回忆保存失败必须分别反馈。

旧内核 `addVisit` 是薄事务接口，由调用者负责规范化；Vue 的类型化 repository 在进入该接口前再次校验并复制输入，不能绕过服务把任意 JSON 当作有效回忆写入。

### 5.2 搜索、进入与分页

搜索同时支持地点名、别名、省份/地区、到访日期和手记。当前 `domain/map-layout.ts` 先按 `provinceId/regionId/visitedOnly` 过滤，再用 NFKC、转小写、去空白匹配；旧版对应 `map-layout.js`。全国“我的足迹”可找回跨省记录，进入省区后只显示该省地点；不包含图片语义识别、OCR 或全文检索引擎。

匹配到某段回忆时，列表展示对应日期/封面/摘要；详情优先显示匹配记录，用户可切回该地点全部回忆。若只匹配地点信息，则正常显示该地点回忆。

按 `placeId` 建立内存索引，按到访日期、创建时间降序及 ID 排序。旧版在 `state.visits` 数组替换后重建；Vue `computed` 从 `visits.value` 生成索引，保存、删除、撤销的后备分支也替换数组。

详情每次展示 8 段，列表每次 12 个地点。`loadIndex()` 收集的是全部摘要和封面，并以 `visits.count()` 核对数量，不读取全库图片行；这仍不是元数据游标分页。摘要包括手记和自定义地点信息，记录极多时其内存仍须测量。

`PhotoThumbnail.vue` 通过共享 `createPhotoLoader(repository)` 读取可见封面，IntersectionObserver 离开可见区域即清除 DOM 图片并取消请求。loader 最多并发 2 次单记录读取，LRU 最多保留 12 张指定原始照片，没有完整 Visit 缓存；它仍需读出一整条 Visit 后提取目标照片，并未物理分表或生成更小缩略图。取消中的底层读取未结束前继续占用并发槽；清理/关闭取消排队与消费者，迟到结果不能回填缓存。

看图、编辑、删除、分享入口由 App 按 ID 读取完整记录并传 `expectedRevision`；摘要版本变化会清理照片缓存。读取失败或写入后索引尚未重新确认时，保留已显示文字但使索引失效，禁止继续基于旧摘要打开/写入，提供重新读取入口。照片占位失败不拦截原父按钮，用户仍可显式尝试读取完整记录。

地图聚合使用屏幕像素距离，聚合锚点保留真实成员坐标；“几处”表示附近地点数量，红点来自已记录状态，不表示到访次数。

`FootprintMap` 将地标矩形和名称、控件、聚合数量障碍传给纯 `layoutMapCovers()`，先选中项再按 ID 稳定排版。照片先右、再左、再下；正常外框 52×48px、紧凑外框 48×48px，分别对应 48×44px 与 44×44px 纸面，间隔至少 4px、视口边缘 8px。地标主体保持 54/58/64px 档位，照片无位置则折叠，不挪坐标或放大照片盖住雪山；锚点离开视口不生成孤立封面。聚合仅用锚点自己的照片，多张才画后缘，单张不假叠片。地图 `photo-cover.ts` 与列表 `PhotoThumbnail.vue` 共用 loader，可见才读，重绘、离屏和销毁会取消并释放；这不是将整本图库载入 Leaflet 图标。

### 5.3 草稿 CAS 与多页面恢复

编辑变化经 450 ms 防抖进入串行持久化队列；每个任务在真正执行时使用最新已提交的 `draftVersion`，不是提前捕获过期版本。

`saveDraft(draft, {expectedVersion})` 与 `clearDraft(id, {expectedVersion})` 在同一 `drafts` 读写事务中比较当前草稿 ID/版本，再写入或删除。这是比较后交换（CAS），不是“最后一个页面覆盖前一个”。

- 每次成功保存产生新的随机版本；旧 token 不能覆盖新版，也不能复活已清空的草稿。
- 草稿冲突保留本页输入，载入另一页草稿需要二次确认；取消不替换内容。
- 正式记录与草稿清理是先后两个事务，不是跨 `visits`/`drafts` 的整体原子提交；编辑器检查已提交内容，避免失败重试再次新增同一记录。
- 另一页已提交同 ID 的不同内容时，提供二次确认“另存为新回忆”，生成新记录 ID，不覆盖原条目；同日同地点可能出现两条。
- 原 8767 构建在另一页清空后仅保留本页输入。开发版已提供检查状态后明确确认另存草稿；确认时事务再次检查槽为空，另存后仍需正式保存，不能自动覆盖另一页后来创建的草稿。
- 新保护不能约束仍运行旧脚本的页面，更新后应关闭旧页面；不应宣称支持多人实时协作。

编辑器记录 ID 和草稿版本优先用 `crypto.randomUUID`，不可用时用 `crypto.getRandomValues` 强随机后备；两者都缺失则提示失败并保留内容。此兼容不等于普通 HTTP 自动具备系统分享能力，也不改变服务监听范围。

### 5.4 编辑、删除、撤销

编辑保存保留打开时的 `originalVisit`，调用 `updateVisit(visit, {expectedVisit})`。存储层在事务内规范化并比较当前行与原快照；不存在或已变化则拒绝陈旧写入。

修改照片/地点时，同一事务移除因此失效的 `covers` 引用，其他记录或仍有效引用不动。删除也要求原快照，在 `visits` 与 `covers` 同一事务中移除记录及关联引用。

删除返回 `{visit, covers}` 作为当前页面内存中的撤销凭证；仅最近一次可撤销，刷新/离开后失效。撤销先检查原 ID 未被占用，且不覆盖之后新选的地点封面。删除不触及设备相册。

### 5.5 私人备份与恢复

正常导出统一走 v2：`loadIndex()` 固定有序摘要、covers 与 revision R → 串行 `readVisit(id,{expectedRevision:R,signal})`，核对完整记录白名单投影与摘要 → 权威 codec `writeVolumes` 逐卷等待暂存完成 → 逐卷 `wrapVolume` 复核并计算成品字节 → 最后 `assertRevision(R)` → 暂存库 CAS 标记 ready。它生成未加密副本；每图 10 MiB、每条最多 9 图、每卷包装后最多 100 MiB 的格式边界保留。旧 `serialize`/`prepareExport` 及 v1 的 100 MiB/2000 条边界继续兼容，不在新交互入口收集全库。

`writeVolumes` 共用原标准化、NDJSON 顺序、UTF-16 代理对分割、SHA-256 后备与规范清单序列化，只保留当前 Visit、单卷工作缓冲和轻量元数据。`wrapVolume` 校验清单哈希、实际 Blob 字节及解码后的 UTF-8，再生成一份最终文件；首卷含完整清单，其余卷不带。不可取消的 digest、Blob 读取和已经开始的事务必须实际结算，才能返回取消并释放本次所有权。

`loadIndex`、`readVisit`、`assertRevision` 的取消等待只读事务真实完成/终止；后者仅读取 `libraryMeta`。主库和导出库没有跨库原子锁：ready 是已经完成的 R 快照，最后版本检查之后主库变化不影响这份旧快照有效性，也不宣称它始终最新。恢复 ready 会话逐卷核对完整性；下载重用原 archive ID/时间/字节，不能从当前主库补缺卷。`BackupExport` 先准备一卷再由用户点击，切换、清理或卸载撤销旧 URL；“已发起”不等于已落盘。

v1 导入：选文件 → 格式及完整图片解码检查 → 合并预览 → 用户确认 → 同一事务重读与合并 → 提交。

v2 导入：选齐整套 → `preflightFiles` 验证字段/清单/哈希并返回原对象描述符 → `consumeVolumes` 第二遍校验、逐张解码、逐条等待暂存写入 → `finishImportStage` 核对实际行/数量/引用并标记 `ready` → 预览 → 用户确认 → 一个跨 store 事务按游标重核正式库、写入记录/封面和 `committed` 收据。`parseFiles` 仅保留兼容，交互式恢复不收集完整快照。

预览不锁库；最终确认重新核对之后发生的新增、编辑、删除和封面变化。首次成功返回 `replayed:false`，同一已提交会话再次确认返回 `replayed:true`，不会重新写入；清理仅删除指定会话暂存并保留收据。读取到 `committed` 预览也须明确呈现既有结果。检查/暂存/预览支持取消，最终确认事务不提供取消参数，界面锁定至结果返回。清理失败单独提示重试，不把已提交数据报作未导入。

界面不生成或导入零记录备份，但 codec 可以表示合法空快照；空库、空文件、合法零记录 JSON 与读取失败不能混为同一种状态。完整图片解码由旧 `backup-ui.js` 或 Vue `BackupPanel` 的平台解码器提供；v2 codec 强制要求解码回调，底层存储仍不自行解码图片。绕过完整恢复服务直接调用存储不等于图片已验收。

只增加缺少的记录；同 ID 同内容跳过，同 ID 不同内容拒绝整次导入。自定义地点同 ID 不同名称/坐标也拒绝；已有地点封面优先。事务失败不留下半份导入，草稿不在导入范围。

此流程是 **追加式合并**，不是整库快照回退：缺席于导入文件的本地行不会被删除；没有删除墓碑，旧备份中已在本机删除的行会被当作缺少记录加入。相同导入在内容不变时可去重，但不能宣传为多设备同步。

`normalizeSnapshot` 按当前格式白名单生成导出字段；未知扩展字段不会进入正常化结果。存储层的部分更新会保留当前原始行的额外字段，但这不构成备份对未来任意字段的无损兼容承诺。

2000 条是 v1 的格式边界，不是新增记录的全库配额。v2 的交互导出与恢复都已避免同时收集全库照片与全部分卷，首页使用摘要；正式库 `load()`、v1 导入等兼容 collector 仍保留。全库摘要、单条最多 9 张照片及一个卷的编码/包装仍有实际工作集，不能宣称全应用固定内存。下一工程项是容量、峰值内存和慢设备量测，按证据再决定照片拆分或缩略图，见 [下一步计划](下一步计划.md) 与 [增量恢复方案](大备份增量恢复方案.md)。

[增量导出方案](大备份增量导出方案.md) 主流程已实现，并完成限定桌面 2101 条/360 图、超过 125 MiB 的真实下载/恢复。主库继续 schema 4；不依赖上传、收费服务或文件系统权限 API。受控测试覆盖配额失败与所有权竞态，原生验证覆盖取消、双页封面版本冲突和指定清理；原生配额耗尽、真机峰值与完整异常矩阵仍待测，不能扩展为任意设备容量认证。

### 5.6 回忆卡输出

Vue 分享卡已接入，桌面浏览器结果见 [历史分享卡报告](../../shanhai-app/qa/sharecard-20260907/REPORT.md) 与 [验证记录](../../shanhai-app/qa/sharecard-20260907/verification.json)。该阶段结果不覆盖系统文件落盘、真实发送或真机。

从单段回忆建立一次独立快照，用户最多选 3 张照片并按原记录顺序输出，可编辑最多 100 个 Unicode 码点的卡片文字。手记默认不带入，日期默认不勾选；生成 1080×1440 PNG 预览，再由用户决定输出。

`App.openCard` 从受信 catalogue 查找地点，固定该次地点名与渲染器目录接口；不从未验证的输出字段接受标题。`MemoryCard` 打开时复制照片 id/url 和当前记录文字/日期，后续同一记录刷新不替换该选择。渲染器只收到已选照片、主动填写/带入的文字和勾选后的日期，输出独立平面 PNG，不附其他回忆、精确坐标、原备份或未选手记。卡片修改不回写 repository。输入调整会使旧预览失效，生成代次防止异步旧结果覆盖新选择。

标题按可用区域排版，60 字自定义地点已做浏览器检查；照片保持完整比例。预览 `<img>` 绑定生成结果的 `width/height`，预留 1080×1440 的比例，避免图片解码后突然改变布局；390/320 宽度无横向溢出，分享文字输入为 16px。这些是桌面窄屏证据，不是手机验收。

系统分享须同时满足安全上下文、`File`、`navigator.share` 和 `navigator.canShare({files})` 能力，并由用户点击触发。只提交当前生成 PNG；取消/失败保留下载路径，不自动重发；系统 Promise 成功不代表接收者收到。

不支持时保留“保存图片”。普通局域网 HTTP 通常没有系统分享条件；当前没有为此自动开启 HTTPS 或公网。图片下载与发送的最终结果需用户在设备上确认。

## 6. 前端信任、安全与故障边界

输入边界是本机选择的照片、手记、自定义地点和备份文件，均按不可信数据校验。旧版动态文字使用 `textContent`，Vue 使用文本绑定；地标 SVG 来自维护的代码，外链仅接受 HTTPS 并带 `noopener noreferrer`。

正式存储操作只在 IndexedDB `transaction.oncomplete` 后报告提交，不把单个请求成功当作落盘完成。空间不足、权限拒绝、连接关闭和版本占用有专门反馈；失败时保留当前页面，不引导清除网站数据。

当前 Vue 摘要缺失、结构不合规、数量或引用不一致时，`loadIndex()` 整次拒绝，不静默跳过记录或修复原始行。单条打开仍校验完整内容。备份碰到不支持或冲突内容会失败，而不是擅自丢字段修复全部历史数据；旧版“跳过不可读行”的历史表现不能当作新索引契约。

页面重新获得焦点/可见时，在没有打开编辑、删除、照片或卡片等交互面板的前提下重新读取；没有实时消息总线、跨设备冲突合并或保证即时刷新的订阅服务。

### 6.1 提交边界与恢复责任

下表正式记录/封面写事务在当前 schema 4 中还包含派生 `visitIndex` 与 `libraryMeta` 的同步维护；表内基础职责不表示它们分开提交。

| 操作 | 真正的提交边界 | 随后失败怎么办 |
| --- | --- | --- |
| 草稿保存 | `drafts` 比较与写入事务完成 | 未提交时保留本页输入；版本不前进 |
| 新增回忆 | `visits` 新增事务完成 | 草稿清理是后续事务；失败按已提交内容去重重试，不重做盲目新增 |
| 编辑 / 删除 | `visits` 与 `covers` 同一事务完成 | 视图刷新失败不等于数据操作失败；提示重新读取 |
| v1 备份导入 | 在同一事务内重新读取、计划、写入 `visits/covers` | 提交前失败整体回滚；提交后刷新失败保留已导入结果 |
| v2 备份导入 | 同一事务重核暂存/正式库，写入 `visits/covers` 及 `committed` 收据 | 提交失败整体回滚；之后清理/刷新失败单独报告，收据防止重放 |
| v2 备份导出 | 逐卷暂存事务完成；最终主库版本检查后以暂存会话 CAS 标记 ready | 只清本次拥有的临时副本；已 ready 后的清理与主库写入无关，清理失败可重试 |
| 卡片生成 | Canvas 返回 PNG，仅代表预览可用 | 不属于 IndexedDB 提交；下载/系统交付需另外确认 |

读取失败、连接占用、配额不足、记录过期与草稿版本冲突是不同恢复分支。界面可显示 `friendlyMessage`；工程记录保留 `code`、操作阶段及可复现步骤，不记录用户完整照片或手记正文。正式页面当前没有新增日志上传端点。

### 6.2 回退不是清库

- 替换 `index.html` 只回退程序，不会回退 IndexedDB 内容或 schema；旧程序可能无法读取新结构，或绕开新版草稿保护。
- 上一阶段原生同源实验确认：旧 schema 2 页面再次读取已升级的 schema 3 库会拒绝，旧界面呈现泛化的存储不可用提示，升级后数据签名未变。这是回退约束，不是可忽略的空库或清库理由；当前不能宣称旧 UI 能无缝降级读取新库。
- 数据库升级前应先在隔离副本验证迁移和旧数据兼容；重要草稿先保存为正式回忆，再由用户导出备份。没有备份时不以清库换取启动成功。
- 若更新后出错，先保留出错页面与用户输入，再判断是只需修复程序还是需要经过确认的数据恢复；不得自动导入旧备份假装还原到更新前。
- 原备份、下载图片、已发送文件是独立副本；删除数据库里的记录不能撤回这些文件。

“本机保存”不等于应用级加密或永久保存：同一设备/浏览器来源内可访问记录；清理网站数据、隐私会话结束、设备故障或浏览器回收可能丢失内容。私人备份应由用户自行保管。
