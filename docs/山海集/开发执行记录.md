## 2026-09-07：增量导出与桌面原生大库文件往返（历史阶段）

本轮落实 [增量导出方案](大备份增量导出方案.md) 的主流程，保留原始中国境内交付目标和现有地图/照片风格。正常导出已移除整库 `load()`/`prepareExport()`；主库保持 schema 4。原 8767、5178、5179 服务与字节未替换，当前新包实际解压服务为 `http://127.0.0.1:5181/app`，没有公网部署。

### 实现与复核

- 权威 `backup-codec.js` 新增 `writeVolumes(source,sink)` 和 `wrapVolume(archive,payload)`，共用已有规范化、NDJSON 顺序、UTF-16 安全分割、SHA-256 后备与规范清单哈希；逐卷等待 sink 完成，只有一份活动 payload。首卷完整 manifest、实际 UTF-8/sha/bytes、JSON 转义后 100 MiB 上限均校验，旧 v1/`prepareExport` 保留兼容。
- `local-store.js` 新增仅读取 `libraryMeta` 的 `assertRevision`；`loadIndex/readVisit/assertRevision` 取消等待真实只读事务结算。WebCrypto digest 和 Blob 读取不能实际中断，因此新导出等待底层结束才报取消，防止清理与下一次生成叠加。
- `export-types.ts`、`export-store.ts`、`export-service.ts` 提供轻量描述符、独立 `${dbName}-exports-v1` schema 1 `sessions/parts` 和编排。固定摘要与 revision R，串行读取完整记录并核对投影，逐卷暂存、复核包装，最后版本栅栏后 CAS 标记 ready。主库只读、版本不递增；ready 是 R 的完整副本，之后主库变更不自动作废它。
- `BackupPanel` 用 `BackupExport.vue` 子组件管理生成、卷列表、单卷准备与真实点击下载、显式继续和清理。切换前撤销上一 URL，取消时保持忙碌锁，卸载阻止迟到链接；点击只标“已发起”。私有 writer token 不进入公开描述符，自动清理两阶段核对所有权；随机 ID 冲突不能误清其他会话，损坏元数据保留可见的指定清理入口。
- 复核发现的来源读取提前取消、损坏元数据不可处理、quota/stale 文案及 ID 碰撞清理归属均已修复，新增受控竞态测试；修改仅机械同步到生成内核，没有另写一套 v2。
