### 进入扩大试用的条件

- 不存在尚未处置的误删、旧版本覆盖、虚假保存成功等数据安全缺陷；发现时立即暂停扩大试用并优先修复。
- 对拟支持的设备，记录、刷新找回、备份恢复必须有实际结果；未覆盖的设备明确排除在“已验收支持”之外。系统分享不支持时，下载回退须实际可用。
- 每项失败须有负责人、严重性、下一动作；“等待用户/设备”不是“通过”，部分功能不适用也不能从报告里消失。
- F01 操作完成仅说明流程可继续验证，不代替全国覆盖的数据与跨区域验收，也不能推导商业化结论。

| T3 形成分享内容 | 有真实分享意图时，制作一张愿意发给朋友看的卡片 | 照片选择、文字、隐私、预览和图片输出是否清楚 |
| T4 自主交付 | 参与者自行选择系统分享或保存后发送，并确认结果 | 文件是否落盘、是否发出；没有真实发送意图则记为未测试 |

每次只安排一个任务。记录结果为“独立完成 / 提示后完成 / 未完成 / 技术条件不足未测试”，并写明主持提示；未收到回答不记为失败。任务要求的再次使用不算自发回访。

T2 当场刷新主要验证保存和当前可找回性，不足以证明长期回忆价值。只有用户愿意、且之后出现实际回看需要时，再记录一次稍后找回；如人为约定回访须标为受邀任务。本计划不会自动设置提醒或监控用户。

## 5. M2：手机与数据恢复验收

### 访问方式先确认

默认继续保留电脑原地址，不自动改服务监听或部署。真机可以由用户按当前说明主动选择可信局域网试跑；需要免配置远程朋友试用时，再独立讨论 HTTPS 静态托管。

- 手机与电脑、不同主机名或端口不共享本机记录；迁移要主动导入备份。
- 不为显示系统分享按钮绕过浏览器安全限制。普通局域网 HTTP 下优先验证下载后发送；系统分享另在设备支持的环境验收。
- 公网托管不等于云同步；托管页面、账户与照片后端是三个不同决定。
- 不自动开放端口、防火墙、公网隧道，不发送邀请或上传私人数据。

### 真机矩阵

至少覆盖可获得的 iPhone Safari 与 Android Chrome；开始时记录实际设备、系统和浏览器版本。缺设备就标未测试，不以桌面窄屏代替。

| 场景 | 重点 | 通过条件 |
| --- | --- | --- |
| 从相册选照片 | 横竖方向、JPEG/HEIC 解码、重复选取、照片上限 | 正常图片可处理，失败可理解，不丢其他成功照片 |
| 新增/编辑/刷新 | 软键盘、日期选择、封面、保存锁定 | 正式保存后再次打开内容正确 |
| 草稿中断恢复 | 等待自动保存后离开，再回到同浏览器同来源 | 草稿恢复；失败不提示虚假的保存成功 |
| 地图与页面滚动 | 单指滚动、双指地图、点聚合、返回详情 | 不被地图困住，能进入目标地点 |
| 检索 | 记得地点、日期或手记片段；旧记录和分页 | 打开正确的回忆，清空筛选能恢复 |
| 图片交付 | 原生分享支持/取消/失败，下载及文件检查 | 参与者可确认实际落盘或交付，不只看到成功文案 |
| 备份恢复 | 在无重要数据的独立来源主动导入备份 | 照片、手记、自定义地点和封面保持 |

严重存储失败和跨页冲突在专用隔离数据库中测试，不用真实珍贵照片做配额耗尽、损坏草稿或并发删除实验。

## 6. M3：工程待办及验收条件

以下列出当前实现状态与剩余验收。真实试跑发现的阻断问题可调整排序，但已完成的增量恢复和 Vue 编辑迁移不重新列为“尚未开始”。

### P0：保存或恢复阻断

- 若出现照片保存失败、刷新丢失、备份恢复错误、误删/覆盖，先停止扩大试用。
- 记录具体入口、错误提示、版本、输入格式和是否已有备份；不要求提交完整私人档案。
- 修复必须包括原问题复现、同类失败回归、成功路径及现有数据兼容检查。

### P1：草稿另存已实现，继续新构建等价验收

原 8767 构建曾缺少这一入口；开发版已实现检查状态后确认另存，并保持 CAS 空槽检查。旧版双页浏览器和受控竞态证据已存在，Vue 也已迁入相关逻辑。

后续全量浏览器验收保持以下条件：

1. 展示会保存什么、另一页草稿是否存在，不擅自更改当前输入。
2. 用户明确确认后才创建新的草稿/记录身份；若共享草稿槽被其他页占用，仍应拒绝覆盖。
3. 保持照片、地点、日期和文字；失败重试不能重复新增多条。
4. 覆盖“原草稿已清空 / 已被换成另一份 / 确认时又发生变化 / 保存后清理失败”测试。

不能通过重置过期版本强行保存，也不能将所有冲突自动合并。此项剩余是新构建验收，不是重新设计已经落地的恢复入口。

### P1：系统分享与下载实机细节

- 验证不同设备的分享支持、取消、等待、文件命名和实际保存路径。
- 系统面板未结束时保持防重复提交；如果观察到困惑，改提示而非假装已取消系统操作。
- 通过条件是用户确认文件或发送结果；PNG 预览生成成功不是最终交付成功。

### P1：备份容量与“恢复”的真实含义

原 v1 受 100 MiB / 2000 条限制，全库新增却没有同等上限。v2 分卷、增量恢复及当前正常增量导出已解决交互主流程的全库收集；首页与查重使用摘要，按需读取指定记录和可见照片。旧 `prepareExport`/v1 collector 保留兼容。当前剩余是原生/手机配额、单条大照片与全库摘要工作集、首载及迁移耗时。

- 保留早期受控增量证据；历史增量导出阶段补充了 2101 条/360 张真实可解码合成照片、9 卷约 140 MiB 的桌面 OS 落盘与当时最终包回导，本轮全国版另有三省 3 条/4 图往返。继续量测首次读取、完整解码、导出阶段耗时和峰值工作集，不能把实验页时点 heap 或窄屏截图当作手机容量结论。
- [增量导出方案](大备份增量导出方案.md) 的固定 revision、逐条读取、兼容 v2 逐卷暂存、最终版本栅栏及单卷下载已实现；独立 `${dbName}-exports-v1` schema 1，主库继续 schema 4。ready 续下、损坏元数据识别、明确清理和私有 writer 所有权检查已接入，继续补真实配额及完整异常矩阵。
- 取消/配额不足只清本次拥有的 session，不退回全库 RAM、不删正式记录；临时副本未加密。先暂存完整 manifest 再下载，只保留一个导出 Blob URL；点击仍只标已发起。桌面这一组 OS 往返已验证，手机文件流程另外验收；小库 v1 快速路径未实施，未来须有明确内存预算。
- 测量 schema 4 游标投影在大库/慢设备的耗时：8 秒打开超时和关闭已有事务取消/提交边界保护，但真实迁移时限尚未证明；不能仅延长超时、跳过坏行或删旧库求通过。
- 区分三种容量：全部摘要、最多 2 条正在读取的含图 Visit、12 张缓存原照片；尚未物理分表、没有更小缩略图。需要真实测量后再决定 Blob 分表/缩略图，不把“按需”写成固定总内存承诺。
- 现有备份导入会保留当前新增行，并可重新加入后来删除的旧记录；验收要包含这个用例，避免用户误以为支持整库时间点回滚或删除同步。
- 同一已提交 v2 会话的收据重放必须返回已提交，不能复活之后删除的行；重新选择文件创建新会话则是新的合并。两者应有不同验收结果与提示。
- 超限时先保留数据与页面，不为获得一个成功导出而删除重要记录；没有可用方案则限制扩大使用，并明确告知。

### P2：有证据后再改体验或性能

- 用户不知道如何找回：先改搜索提示、空结果和地点/回忆信息层级。
- 输入负担明显：先优化照片、地点确认和封面操作，不默认接入 AI 自动识图。
- 手机上照片多时卡顿：沿用已验桌面合成样本量测导入、检索与长列表；桌面大库往返不能推导慢手机性能，避免测试触碰真实数据。
