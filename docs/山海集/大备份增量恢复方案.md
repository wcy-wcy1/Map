## 问题与现状

早期分卷 v2 使用 `parseFiles` 将整库重建到 JavaScript 内存，再由 UI 逐图解码；这是本方案修复的问题。当前旧开发界面与 Vue `BackupPanel` 已改用 `preflightFiles` → `consumeVolumes` → IndexedDB 暂存 → 原子合并。`parseFiles` 仅保留兼容 collector，不进入交互式 v2 恢复。

受控增量与暂存验证及本轮限定桌面大库文件往返已通过，不能据此声称全应用内存有界或手机容量验收完成。schema 4 首页/查重使用摘要，地图/列表/详情按需读照片；正常导出经 `BackupExport` 固定版本、逐条读取和逐卷暂存。正式库兼容 `load()`、v1 导入和旧 `prepareExport` collector 仍保留，均不进入新的交互导出路径。

不通过简单新增总容量阈值解决：历史版本已经允许累计保存，新增阈值可能重新制造“已经保存却不能恢复”的问题。不删除已有回忆，不静默分批修改正式库。

## 当前实现：增量暂存，再原子合并

```text
选齐文件 → 整套预检 → 第二遍逐卷校验、逐条解码并等待暂存 → ready 与数量预览
                                            ↓ 用户确认
                               一个事务重新核对并合并正式库
                                            ↓ 提交成功
                              committed 收据 + 清理本次临时数据
```

1. `preflightFiles` 验证完整文件集合、严格字段、编号、清单及哈希。v2 仅返回不可伪造的元数据描述符；必须将同一 codec 实例返回的原对象交给 `consumeVolumes`，不能克隆、持久化或重建描述符。v1 继续返回单文件快照。
2. `consumeVolumes` 第二遍逐卷重新校验，照片逐张解码，每条回忆和封面回调都等待写入完成再继续。取消等待已开始的 sink 结束后清理，避免清理后出现迟到的暂存写入；不收集完整回忆/照片对象数组。
3. 历史 schema 3 增加 `backupImportSessions`、`backupImportVisits`、`backupImportCovers`；当前 schema 4 另加 `visitIndex/libraryMeta`，保留原 `visits/covers/drafts`。暂存与正式数据在同一数据库内；最终合并还在同一事务维护无照片字节摘要和库版本，不在提交后异步补索引。
4. 暂存区采用单独随机会话身份；缺少、重复、未知关联、计数不符均不能进入 ready。清理仅针对已确认的会话，不使用整库清空。
5. 预览是提示，不是锁。确认后在一个 readwrite 事务内以游标顺序处理，重新核对正式库；相同记录跳过、同 ID 不同内容整笔拒绝、当前封面优先。
6. 配额或冲突使本次正式变更整体回滚。`committed` 状态、收据与正式写入同事务提交。首次成功返回 `replayed:false`，同一已提交会话再次确认返回 `replayed:true`；清理保留收据，不能因之后删除某条正式记录而重放该会话使其复活。重新选择旧备份建立新会话仍是新的追加合并。
7. 检查、解码、暂存和预览阶段支持取消；只清理明确会话。最终 `commitStagedImport(id)` 没有取消参数，确认后界面锁定操作，等待事务完成或失败，不以关闭 UI 假装撤销。清理失败单独提示并提供重试，不把已提交记录报作导入失败。

## 接口与所有权

- 编解码权威源码：`output/shanhai-lijiang-records/backup-codec.js`；v1 parse/serialize 和边界保留。
- 存储：`local-store.js`；新增 `beginImportStage`、`stageImportVisit`、`stageImportCover`、`finishImportStage`、`planStagedImport`、`commitStagedImport`、`discardImportStage`。
- Vue：`src/generated` 是机械生成的相同内核；`src/services/contracts.ts` 明确接口，`backup-service.ts` 编排恢复，`BackupPanel.vue` 负责交互。`sync:kernels` 更新生成物，`verify` 检查与权威源码一致。
- UI：旧 `backup-ui.js` 和 Vue `BackupPanel.vue` 的 v2 均使用暂存、预览、确认、取消和清理重试；v1 保持既有流程。
- 会话恢复：明确恢复 `ready` 会话，识别 `committed` 收据；不完整 `staging` 不会自动进入正式库。清理仅针对具体会话，保留其他页面的暂存。数据库切换沿用 `versionchange` 关闭旧连接保护。
- 摘要访问：`loadIndex()`、`readVisit(id,{expectedRevision,signal})`、`hasDraft()` 用于首页/具体记录/草稿入口；照片仍内嵌完整 Visit，2 并发与12 单照片 LRU 不代表照片已经分表。升级 8 秒超时或关闭会等活跃升级 abort 确认再报失败，不能将已过提交边界伪报为回滚；慢设备迁移仍待测。

## 支持边界

继续保留每图 10 MiB、每条最多 9 图、每卷最多 100 MiB 的现有格式边界；默认卷内容约 16 MiB 字符。没有宣称无限物理存储。`navigator.storage.estimate()` 只能作提示，不能证明空间足够或改变原子性。

旧大图库不因新总量常量被判作无效；按增量流程尝试恢复。真实空间不足时保持正式库不变，保留外部文件，允许在空间充足的设备/来源重试，不要求先删除重要回忆。单条 9 张大图本身仍可占较多内存，若真机不满足，需进一步按照片暂存，而不是提升超时或忽略解码。
