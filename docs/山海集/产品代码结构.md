## 1. 先认清当前入口

当前前端工程化开发入口是 [shanhai-app](../../shanhai-app/README.md)，独立业务后端入口是 [shanhai-api](../../shanhai-api/README.md)。原完整试用构建仍来自 [output/shanhai-yunnan](../../output/shanhai-yunnan/README.md)，其备份/存储权威源码还位于 `output/shanhai-lijiang-records`。后端不进入前端构建或 ZIP，工作区里其他无关后端项目不参与山海集构建。

- 当前省区和目录：34 个省区、49 个 Region；公共 43 点仍全部属于云南旧 16 州市，其他 33 区只有省级记录区域。个人地点可跨省保存，不计作公共目录覆盖。
- 当前开发/独立试用包前端：Vue 3、TypeScript、Vite、Leaflet；原 8767 保留原生 HTML/CSS/JavaScript 构建。不能混用两套启动命令或把省区扩展称为全部产品目标完成。
- 当前本地服务：旧 [serve.py](../../output/shanhai-yunnan/serve.py) 使用 Python 标准库；Vue 开发使用 Vite，独立包 [serve.mjs](../../shanhai-app/scripts/serve.mjs) 使用 Node 标准库。它们均为静态交付，不是业务 API。
- 独立后端1.9阶段运行于 `127.0.0.1:5190`，API和注入的 `/qa` 同源；默认启动只提供 `/api/v1`，不托管QA或照片目录。PostgreSQL17.10专用角色非超级用户，开发/测试库隔离。5192实际Vue/account/outbox接通已有独立证据；旧库迁移、持久固定快照、正式身份仍未完成。
- 当前前端本机存储：IndexedDB，默认库名 `shanhai-lijiang-local-v1`。原 8767 构建 schema 2，上一阶段 5176 包 schema 3，当前权威内核和 Vue 主库 schema 4。增量导出另用 `${dbName}-exports-v1`，schema 1，仅有 `sessions/parts`，不升级主库。v1 为 `shanhai-backup`，v2 为 `shanhai-backup-volume`，数据库名、schema、备份格式分别计版本。
- sixfoot、Flask 等工作区其他项目不是本产品后端，不参与本页面构建。

虽然目录名为 `output/`，这里同时保存可维护源码和构建结果。不要误以为可以删除后重新生成整个目录。

## 3. 构建过程与真实脚本顺序

Vue：`main.ts` 仅在127.0.0.1且pathname恰为 `/connected` 时懒加载 `RemoteApp.vue`，其余挂载普通 `App.vue`、不探测API。账号外壳检测 `testIdentityOnly:true`，通过TravelServices注入App并按账号世代卸载私人树；普通 `createTravelServices` 沿用catalogue/platform/dbName。模块导入不打开匿名库。`npm run verify` 检查内核/地理新鲜度、类型、测试和构建并保存哈希。

### 4.1 新增后端职责与提交边界

`app.ts` 装配Auth/Records/Photos，检查本机Host/Origin，私人响应绑定账号、禁缓存并使用统一错误。`auth.ts` 仅提供显式alice/bob测试身份及12小时会话；业务写入要求会话、CSRF和幂等键。Vue account/outbox另有1.10实现，不能据此宣称OIDC/TLS、云同步或旧库自动迁移完成。

`remote/store.ts` 的 `shanhai-account-v1-<UUID>` schema1只含cache/draft/outbox；完整提交和cursor同事务应用，草稿保留读出时CAS版本。结果未知的操作保存原输入/键/步骤，先查收据重试；已完成后清除输入照片。同草稿明确另存时原目标终态冲突与新草稿原子归档，未知pending阻止换身份；关闭编辑器后的摘要刷新在App负责。账号备份恢复/删除撤销主动拒绝；首次同步回放全部保留change，不是固定快照。2并发/12图片缓存不保证outbox全库读取的内存上界。

`db.ts` 以同一连接/事务取得账户锁并重核会话，`records.ts` 完成 owned 查询、字段/关联验证、CAS、业务写入、完整 change 和幂等收据。`custom_places`、`visits`、`photos`、`map_covers` 等表有带 owner 的复合外键；服务端自定义地点独立存储、照片只在记录中保留有序引用，不能直接替换前端嵌入式 `customPlace` / data URL 模型。删除保留墓碑与 client ID，分页 sync 不拆提交；列表 cursor 失效后重列，不是持久固定快照。

`photos.ts` 先持久创建上传预留和清理意图，再用 5 分钟签名能力接收一次不可变代次；实际长度/哈希/MIME/单页/40 MP 检查后经 sharp 重编码最长边 2400 像素 JPEG。文件读暂错可重试 503，真实图像错误才拒绝并退休。输入/输出各 10 MiB、每账号 500 个占用身份及 100 MiB 保守预算；输出扩张及取消未清理对象均计费。签名下载为 60 秒，逐次核查会话与有效自有记忆，不开放静态照片路径。

清理先提交退休/墓碑，再按精确内部 key 物理删除并确认；失败保留任务。当前是显式 `/cleanup/retry`，无后台 GC 或正式账号清除/保留期策略。`storage.ts` 排他创建对象、拒绝不安全路径；Windows 文件 mode 不替代 NTFS ACL。完整协议和限制见 [后端 README](../../shanhai-api/README.md)，审查与验收分开记录在 [后端报告](../../shanhai-api/qa/backend-20260907/REPORT.md)。

## 5. 数据文件与历史目录不要混用

当前运行数据由 `shanhai-app/src/data/places.json`、`province-boundaries.json`、`yunnan-boundary.json` 和公开 `public/data/yunnan-geography.geojson` 提供；全国源由 `build-national-geography.mjs` 固定 geoBoundaries 提交/SHA256 生成，旧云南省界从 `src/data/geography.json` 原样提取。前两类基础边界组成同步 `regions` 块，完整云南细节通过同源 fetch 读取。

旧版索引按 `state.visits` 数组引用失效；当前 Vue 的 `visits.value` 是 `VisitSummary[]`，照片字段仅 `{id,name}`。`loadIndex()` 返回 `{visits,covers,revision}`，`hasDraft()` 不读取完整照片草稿。保存、删除、导入、撤销后重新确认摘要版本并清理旧照片缓存；读取失败保留画面但禁止基于旧摘要操作。打开具体回忆用 `readVisit(id,{signal,expectedRevision})`，编辑器查重只读摘要，同 ID 比较才读整条。schema 4 在同一正式写事务更新 `visitIndex/libraryMeta`，升级异常不静默重建原库。

增量 v2 入库使用逐条等待的 sink 和游标；普通交互导出已改由 `BackupExport` 调用增量服务，不再完整 `load()`。旧 `prepareExport` 和 v1/全量 collector 兼容入口保留，v1 恢复仍会读取完整库。单次按需读取仍读一整条含图 Visit 再提取目标，照片没有物理分表；loader 缓存的是 12 张单照片原数据，不是缩略图。不能宣称全应用内存有界。

[大备份增量导出方案](大备份增量导出方案.md) 的当前实现由 `export-types.ts/export-store.ts/export-service.ts` 与 `BackupExport.vue` 组成。生成从 `loadIndex()` 冻结摘要、封面和 revision，串行 `readVisit(id,{expectedRevision,signal})` 并核对摘要投影；权威 codec 的 `writeVolumes` 按 canonical v2 顺序输出逐卷 sink，等待每卷暂存提交后再继续。逐卷读回并通过 `wrapVolume` 校验摘要、校验和与精确封装字节数，最后以只读 `libraryMeta` 的 `assertRevision` 确认源版本，再提交 `ready`。该流程没有全库照片数组或全套封装 Blob 常驻；摘要、单条含图 Visit、当前卷与浏览器自身开销仍存在。

`${dbName}-exports-v1` 是独立 schema 1 库，`sessions` 保存状态和无照片元数据，`parts` 按 `[sessionId,part]` 保存 payload Blob；主库保持 schema 4。写入 token 仅存于内部，`ready` 提交后仍保留私有归属，供本次取消清理确认所有权，公开会话不暴露 token。取消/关闭先 abort 并等待实际事务和工作结算；失败清理只触及本会话，清理失败保留可重试状态。损坏的 ready 元数据在可确认 id/sourceDbName 时列为 `damaged`、可显式清理，其他有效会话仍可发现，不将损坏会话当成可下载。

刷新后可主动列出暂存会话，`resumeReady` 重新逐卷校验完整副本；未完成或损坏副本只能清理后重建。下载时只 `readPart`/`wrapVolume` 一卷，`BackupExport` 最多持有一个活动 object URL，切卷、关闭或清理时释放。UI 区分“已生成”“已发起下载”和用户核对文件，清理需明确确认；临时副本未加密且含照片/手记，不随日后编辑更新。该实现不依赖上传、收费接口或文件系统权限 API。
草稿版本与记录 id 依赖强随机源；不得为兼容性改成时间戳或 `Math.random`。仍运行旧脚本的页面不受新版冲突保护约束。

## 9. 浏览器 QA 隔离规则

需真实写入测试时，使用源码提供的独立 QA 路由，启动前确认目标端口空闲：

```powershell
python output/shanhai-yunnan/serve.py --port 8768 --qa --bundle output/shanhai-yunnan/qa/handoff-20260907-a/bundle/index.html
```

例如打开 `http://127.0.0.1:8768/qa-memory?run=handoff-20260907-a`，编号仅用小写字母、数字和连字符。
该路由注入 `shanhai-qa-memory-handoff-20260907-a` 数据库；普通 `/app` 即使在 QA 服务上也不是这条隔离路径。同一来源重复使用编号会复用旧测试数据；要做新一轮空状态检查就换新编号，不通过删除数据库解决状态不明的问题。Vue 单元集成通过明确注入的 dbName 隔离，不能在默认私人库写入夹具；新来源空库不算旧数据升级验收。

原生同源切换使用另一套专用服务：先构建，再执行 `npm run qa:cutover -- 5175`（schema 2 旧 UI 写入），或 `npm run qa:cutover -- 5177`（schema 1 合成历史结构）。仅允许这些显式开发端口，启动前检查没有其他服务或用户数据。`/legacy` 读取保留旧 HTML 并核验固定哈希，`/app` 提供当前构建；它们在同一隔离来源使用同一库名。`/qa` 只读检查不创建空库，合成 schema 1 建库按钮仅在空来源成功；不提供覆盖或删库。旧版 UI 写入和升级前后数据签名均保留于 [历史切换报告](../../shanhai-app/qa/cutover-20260907/REPORT.md)，从未修改 8767 用户库。实验服务和夹具都不得作为朋友试用服务。

- 只使用已明确命名的合成素材；测试双页冲突时两页使用同一 QA 编号，独立用例使用不同编号。
- 不导入测试记录到用户正式 `/app`，不清空正式 IndexedDB，不读取用户照片来生成夹具。
- 默认服务不启用 QA，公开分发包不含 QA 素材；不要将 `--qa` 作为朋友试用启动方式。
- 自动化中的 DOM、事务、Canvas 多为受控环境；真实手机、HEIC、原生分享发送及系统下载需单独验收。
- 新增证据写到新的、可识别的 QA 子目录，记录构建哈希、场景和未测边界，不覆盖历史结论。
