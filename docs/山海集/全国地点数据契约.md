# 全国地点数据契约

日期：2026-09-07。状态：现有全国地图开发数据的兼容约束，以及后续公共地点扩展的接口草案。本文没有建立全国完整景点目录，也不表示已有远程目录服务或业务后端。

本次核对对象：[models.ts](../../shanhai-app/src/domain/models.ts)、[catalogue.ts](../../shanhai-app/src/domain/catalogue.ts)、[provinces.ts](../../shanhai-app/src/domain/provinces.ts)、[geography-service.ts](../../shanhai-app/src/services/geography-service.ts)、[来源生成脚本](../../shanhai-app/scripts/build-national-geography.mjs)。现有字段与下面标为“拟议”的字段必须区分，不能直接将草案字段写进旧备份。

## 1. 当前覆盖口径

| 对象 | 当前数量 | 含义与限制 |
| --- | ---: | --- |
| `Province` | 34 | 可选择的省份、自治区、直辖市和特别行政区；有粗略轮廓 |
| `Region` | 49 | 云南 16 个州市，加其他 33 个省级记录区域；层级不齐全 |
| 公共 `Place` | 43 | 全部位于云南；其他省区没有公共点不代表没有旅行地点 |
| 用户 `CustomPlace` | 按实际记录 | 可在所选省区保存自己的地点；不属于公共目录覆盖统计 |

全国入口显示“43 个公共地点，目前整理于云南”。省区入口分别显示该省的实际公共点数；空目录提供“添加我的地点”。不能用“34 个省区”推导“全国景点已齐全”，也不能把省级 `Region` 展示成已经整理好的城市列表。

## 2. 稳定身份与字段映射

当前类型保持如下语义：

```ts
type Coordinates = [longitude: number, latitude: number]
interface Province { id: string; code: string; name: string; shortName: string }
interface Region { id: string; name: string; placeIds: string[]; provinceId?: string }
interface CustomPlace { id: string; name: string; regionId: string; coordinates: Coordinates }
```

`Province.code` 是数据映射中的六位字符串，来自 GeoJSON `properties.divisionCode`；它与应用主键 `id` 分工不同。这里记录的是当前数据映射，不宣称实时更新的行政区划代码名录。名称、代码与上游名称可以修订，已有应用身份不得因此重写。

| 地区示例 | `Province.code` | `Province.id` | 可存入当前记录的 `regionId` |
| --- | --- | --- | --- |
| 云南 | `530000` | `yunnan` | `lijiang`、`kunming` 等已有州市 ID；不能用 `yunnan` 代替 |
| 四川 | `510000` | `cn-51` | `cn-51` |
| 北京 | `110000` | `cn-11` | `cn-11` |
| 香港 | `810000` | `cn-81` | `cn-81` |

除云南外，当前省 ID 使用 `cn-` 加两位映射前缀；云南保持 `yunnan`，不得迁移成 `cn-53`。已有 `lijiang`、`dali` 等州市 ID 和 `yulong` 等公共地点 ID 同样不变。`Province.id` 的权威集合来自 `provinces`，不能接受任意形如 `cn-XX` 的字符串。

归属链为 `Visit.placeId → Place.regionId → provinceForRegion(regionId) → Province`。当前全部地点的 `Place.mapId` 表示所在省级地图 ID；公共 43 点为 `yunnan`，自定义地点由 `regionId` 推导。`Region.provinceId` 在旧类型中为可选，当前目录构造的 49 项均填入值。

`CustomPlace`、`Visit` 和 `Draft` 目前不新增 `provinceId`。云南旧草稿中的 `regionId=lijiang` 可直接推导出云南；四川草稿存 `regionId=cn-51`。草稿允许 `coordinates=null`，正式回忆不允许。修改自定义地点省区后清空坐标，避免旧坐标被误当作新地区的地点。

## 3. 坐标、归属与边界校验

坐标统一为 WGS84 的 `[经度, 纬度]`，不互换顺序，不把 GCJ-02/BD-09 值直接标成 WGS84。公共点保留 `coordinateSystem`、`coordinateSource`、`anchorNote`；未来外部点源必须记录其原坐标系、转换步骤与坐标版本。未知坐标系先拒绝，不自动猜测。

现有 `normalizeCustomPlace` 同时检查 `custom-` 身份格式、1–60 字名称、受支持 `regionId`、两个有限数值及所选省轮廓。省界算法支持 Polygon/MultiPolygon；外环边界接受，内洞及洞边界拒绝。外省用全国数据的对应多边形，云南保留现有云南边界及其历史预检，兼容已保存的云南记录。

地图可拖动范围只是视窗限制，不能当作正式记录的空间校验。所有新建、编辑、草稿转正式记录、备份恢复和未来后端写入必须经过相同版本的地点规则。客户端校验服务于即时提示，后端仍须重新验证。

这些多边形是粗略示意，可能错误拒绝真实的沿海、岛屿、港澳或省界附近地点。产品应显示具体所选省区与“轮廓较粗略”的说明；不能声称通过校验就证明真实行政归属。保留手记与草稿供重新选择，不通过移动原坐标、放大轮廓或用矩形放行来掩盖限制。

## 4. 来源版本与本次字节基线

- 固定提交：`9469f09592ced973a3448cf66b6100b741b64c0d`。
- 数据代表年份：2019；输入元数据记录 sourceDataUpdateDate 为 2023-01-19、buildDate 为 2023-12-12。生成应用文件的日期不能替代边界年份。
- 原始 GeoJSON SHA-256：`3a00467a0db9b4136facb5f2f3d0edbfd96adb15651cfdf63991da9281030e85`。
- 原始 metadata SHA-256：`b14151296df758f83bc66706929db37eb2114a439b6f0a1e5c9608732d840136`。
- 输入许可字段为 `Public Domain`，但原始 Wikimedia 许可链接缺少具体文件名且格式有误；这不是逐个原始文件完成许可核验的证据。保留该限制与上游署名。
- 源名称 `Guangzhou Province` 映射为广东省，`Ningxia Ningxia Hui Autonomous Region` 映射为宁夏回族自治区。只修正应用名称，不移动或补画几何。

| --- | --- |
| `src/data/province-boundaries.json` | `b6918bc072de0d7c348ab574aa1d76aae3165a350be57e496ba4122330e5d4ab` |
| `src/data/yunnan-boundary.json` | `ce08da530d75b86f327eb8c5715b31b743848400b30407dab4ccb4cf7dc5896e` |

以上是源数据文件的身份，不是应用发布包哈希。全国文件的 `attribution.sha256` 指向原始 GeoJSON 输入，其值与生成文件哈希不同是正常的。云南边界从既有 `geography.json` 提取；其 OpenStreetMap relation 913094 来源信息保留，不能套用全国来源的年份、许可和哈希。

更新流程：固定新上游提交/版本 → 保存原始文件和元数据 → 核对许可与名称映射 → 生成新候选产物 → 校验几何/身份/兼容夹具 → 比较变更点与边界影响 → 产生新清单与回退资源 → 再替换运行时引用。上游内容哈希不符立即失败，不能静默接受。同一版本发布后的字节不可被覆盖。

边界更新改变验证范围时，未来后端使用独立 `validationVersion`；已存记录保留其原校验版本。不能因为新版轮廓缩小就删除旧回忆或使旧库无法打开。新的点位编辑按新规则明确确认，未改位置的旧回忆仍能阅读和导出；规则升级及旧备份恢复需专门兼容迁移，不能只替换 JSON 后默认完成。

## 5. 当前加载边界与拟议分片

目前全国基础边界、云南兼容边界由同步 `regions` 缓存块提供，公共目录随应用提供。云南水系/州市等较大的细节通过 `geographyService.load('yunnan')` 按需 `fetch` 固定同源 `/data/yunnan-geography.geojson`，使用 15 秒超时与 `no-cache` 重验证；失败后可以重新发出真实请求，不使用可能缓存模块失败的动态 import。`base(provinceId)` 先提供当前省轮廓，细节失败保留该轮廓并可重试；取消旧请求后其结果不能覆盖新省区。地图加载不读取、修改或清理个人照片。

未来公共目录增加时，按省区提供不可变地点分片，但“分片未加载”必须区别于“地点不存在”。下列是拟议 HTTP 接口，当前静态服务未实现：

| 端点 | 请求与返回 | 缓存及错误 |
| --- | --- | --- |
| `GET /api/v1/catalogue/manifest` | 返回 `schemaVersion/catalogueVersion/provinces/regions/shards`，以及目录完整度说明 | `ETag`；支持 304；每个 shard 有固定版本、字节数和哈希 |
| `GET /api/v1/catalogue/places?provinceId=cn-51&cursor=…` | 返回 `{items,nextCursor,catalogueVersion}`；分页仅元数据 | cursor 绑定版本；未知省 400；版本过期 410，要求重新取清单 |
| `GET /api/v1/catalogue/places/{placeId}` | 返回稳定地点身份及当前或停用元数据 | 已停用可读，包含 `status/replacedBy`；未收录返回 404，客户端保留私人引用 |
| `GET /assets/catalogue/{version}/{shard}.json` | 内容寻址/版本固定的公开资源 | 哈希不符拒绝入缓存；不得返回用户回忆或签名照片 URL |

拟议清单片段（尖括号内容为契约占位符，不是已发布资源）：

```json
{
  "schemaVersion": 1,
  "catalogueVersion": "<immutable-version>",
  "coverage": { "provinceCount": 34, "publicPlaceCount": 43, "completeNationalDirectory": false },
  "shards": [{
    "id": "places-yunnan", "provinceId": "yunnan", "version": "<immutable-version>",
    "url": "/assets/catalogue/<immutable-version>/places-yunnan.json",
    "sha256": "<64-lowercase-hex>", "bytes": 0, "placeCount": 43,
    "coordinateSystem": "WGS84", "validationVersion": "<boundary-version>",
    "sourceManifest": "/assets/catalogue/<immutable-version>/sources.json"
  }]
}
```

`bytes` 必须由实际产物填入，不能将例子的 0 当作发布值。清单与分片由受控发布来源交付，哈希用于检查内容一致性；哈希本身不证明来源可信。

## 6. 公共地点引用不能随缓存失效

后续每个新公共地点取得不可复用的稳定 ID。改名、补别名、更新坐标或更换图标只增加内容版本；地图名称不能作为主键。合并重名地点时保留旧 ID 的解析记录和 `replacedBy`，不自动改写私人回忆、封面与备份。下架点保留最小元数据与停用状态，仍可展示旧回忆。

客户端需要三个不同集合：常驻轻量身份索引、可卸载的地点详情分片、由用户回忆引用而保留的地点元数据。拟议 `PlaceReferenceSnapshot` 保存 `placeId/name/regionId/provinceId/coordinates/coordinateSystem/catalogueVersion`，但这是未来 schema 的新增结构；当前 `Visit` 尚无该字段。公开名录更新只替换公开资料，不把个人快照当作新版目录上传。

迁移前必须先为已有引用补齐受控快照或常驻身份索引，再启用分片卸载。不能继续用“当前内存里的 `catalogue.has(id)` 为假”否定记录：新建一个公共地点引用需要成功解析；读取已有引用优先保留原身份与快照；临时网络失败显示“地点资料待加载”，仍保留照片、手记与备份能力。恢复旧备份遇到不能解析的 ID 时应停在可重试的暂存阶段，明确缺失清单，不能跳过该条后宣称完整恢复。

自己的地点仍随回忆保存足够元数据；同一个自定义 ID 不得表示两组不同名称/归属/坐标。现有编辑器在这些字段改变时创建新自定义地点身份，避免其他回忆被连带改写。未来服务端沿用此不变量。

## 7. 验收矩阵

以下是数据契约门槛；“需执行”不是已通过的测试结论，当前实现证据应另见本轮 QA 产物。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| D01 | 构建当前目录 | 34 省、49 region、43 公共点；ID 唯一、所有引用可解析 |
| D02 | 读取云南旧库与 v1/v2 备份 | `yunnan/lijiang/yulong` 等身份及坐标不重写；照片、手记、封面保留 |
| D03 | 四川自定义地点保存、刷新、导出回导 | `regionId=cn-51` 可推导四川；不依赖公共景点分片 |
| D04 | 坐标反序、NaN、洞、多边形、省界外点 | 拒绝非法输入；边界策略明确；草稿不丢失 |
| D05 | 全国→云南→四川且云南细节迟到 | 只显示当前 scope；失败可重试；地图加载不触碰记录 |
| D06 | 固定来源文件被改变一字节 | 检查失败；不产出带旧版本号的新数据 |
| D07 | 新版轮廓排除既有合法点 | 旧记录仍可读和导出；新点位编辑有版本化规则与兼容报告 |
| D08 | 分片卸载/离线/地点改名或下架 | 已存回忆和封面可解析；旧公共 ID 不复用 |
| D09 | 备份引用的分片暂不可用 | 暂存保留并可重试；不部分丢弃后报告成功 |
| D10 | 来源说明与 UI 覆盖口径 | 可追到固定输入、年份、许可限制；未宣称官方疆界或完整目录 |

本轮不包括全国城市/区县目录、完整景点收集、导航、实时地理编码、轨迹记录、地图公开发布认证或公共云服务。未来账户照片与同步设计见 [账号照片与同步接口草案](账号照片与同步接口草案.md)。
